# mcpdf

A local MCP server that indexes a corpus of PDFs and exposes semantic search
over them. Embeddings are generated by a local OpenAI-compatible endpoint
(e.g. LM Studio) running on your machine; vectors are stored in a local SQLite
database via `sqlite-vec`.

Useful for any PDF corpus you want to query without round-tripping through the
cloud — manuals, papers, books, internal docs, datasheets.

## Prerequisites

1. A local OpenAI-compatible embeddings endpoint. The reference setup is
   [LM Studio](https://lmstudio.ai) with an embedding model **actually loaded
   into memory** (being listed by `/v1/models` is not enough — it has to be
   loaded). Recommended:
   ```sh
   lms load text-embedding-nomic-embed-text-v1.5
   ```
   Verified with `text-embedding-nomic-embed-text-v1.5` (768-dim, fast, 2k
   context). `nomicai-modernbert-embed-base` should also work but is sometimes
   loaded as an LLM rather than an embedding model — check `lms ls`.

   Any other server that speaks the OpenAI `/v1/embeddings` shape (Ollama,
   llama.cpp's server, vLLM, etc.) should also work — point `LM_STUDIO_URL` at
   it.
2. `uv` (Python package manager).

## Install

```sh
cd mcpdf
uv sync
cp .env.example .env   # tweak DB_PATH / model name if needed
```

> **Why uv-managed Python?** The framework Python from python.org disables
> sqlite3 extension loading, which `sqlite-vec` requires. The `pyproject.toml`
> pins `python-preference = "only-managed"` so uv installs its own interpreter
> (python-build-standalone) where extension loading is enabled.

## Configuration

Environment variables (see `.env.example`):

| Variable | Default | Purpose |
| --- | --- | --- |
| `LM_STUDIO_URL` | `http://localhost:1234/v1` | OpenAI-compatible base URL |
| `EMBEDDING_MODEL` | `text-embedding-nomic-embed-text-v1.5` | Model ID as listed by `/v1/models` |
| `EMBEDDING_DIM` | `768` | Must match the model. Locked at DB-create time. |
| `DB_PATH` | `./mcpdf.db` | Where to store the SQLite vector DB |
| `CHUNK_TOKENS` | `512` | Max tokens per chunk |
| `CHUNK_OVERLAP_TOKENS` | `64` | Overlap between consecutive chunks |
| `EMBED_BATCH_SIZE` | `32` | Chunks per embedding request |

## Bulk-index your PDFs (one-time, recommended)

Indexing the first few thousand pages is far faster from a CLI than through the
MCP tool, because the MCP client adds round-trip overhead per call.

```sh
uv run mcpdf-index index /path/to/PDFs
uv run mcpdf-index search "how do I set the LFO retrigger mode"
```

Re-running `index` on the same path is idempotent — unchanged files are skipped
via SHA-256, changed files are re-embedded.

## Use as an MCP server

### Claude Desktop / Claude Code

Add to your MCP client config (`~/Library/Application Support/Claude/claude_desktop_config.json`
or the equivalent for your client):

```json
{
  "mcpServers": {
    "mcpdf": {
      "command": "uv",
      "args": [
        "--directory",
        "/Users/wgriffin/Source/mcpdf",
        "run",
        "mcpdf"
      ],
      "env": {
        "LM_STUDIO_URL": "http://localhost:1234/v1",
        "EMBEDDING_MODEL": "text-embedding-nomic-embed-text-v1.5",
        "DB_PATH": "/Users/wgriffin/Source/mcpdf/mcpdf.db"
      }
    }
  }
}
```

Restart the client. Tools exposed:

- `index_directory(path, recursive=true)` — add or update PDFs in the index
- `search(query, top_k=8, document_ids=[...])` — semantic search
- `list_documents()` — show what's indexed
- `get_document_info(document_id)` — metadata for one doc
- `remove_document(document_id)` — drop a doc and its chunks/vectors

## How it works

1. **Extract** — PyMuPDF reads each PDF page-by-page, preserving page numbers.
2. **Chunk** — Pages are concatenated into a token stream (cl100k_base for
   budgeting) and sliced into overlapping windows. Each chunk records the page
   range it spans.
3. **Embed** — Chunks are batched and sent to the embeddings endpoint with a
   `search_document:` prefix (Nomic's task convention). Queries use
   `search_query:` for retrieval-aware asymmetric similarity.
4. **Store** — Chunks go in a `chunks` table, embeddings in a `vec0` virtual
   table from `sqlite-vec`. KNN search runs as a brute-force cosine over the
   vec0 table, then joins back to `chunks` and `documents` for metadata.

## Switching embedding models

The vector dim is baked into the DB at create time. To switch from a 768-dim
model to a different one, delete (or move) `DB_PATH` and re-index. There's no
in-place migration — vec0 tables can't be resized.

If you switch to a non-Nomic model that doesn't want the `search_document:` /
`search_query:` prefixes, edit `embeddings.py` and set both `_PREFIXES`
entries to empty strings.
